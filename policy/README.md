# Skylot policy

The transaction-scope WASM validity policy for the Skylot city chain. The rules
it enforces are `../docs/chain.md` ("Records" and "Rules the policy enforces");
every number comes from `../chain/rules.json`.

Module CID: `bafyreibklgjauwc2o7o5adyhg6nfbatmgokoapypu7ulw5gotmuanw65fu`
(in `../chain/spec.json`, built from this crate at rustc 1.96.0).

## Layout

- `src/lib.rs`: the policy. `no_std`, integer math only, on
  [`lattice-policy-rules`](https://github.com/adalinxx/moniker) at tag `v0.1.0`
  (context and body parsing, `check_token_write`, `check_payments`).
- `src/rules.rs`: the numbers from `chain/rules.json`, generated by
  `tools/gen-rules.mjs`. Don't edit it by hand.
- `src/tests.rs`: native unit tests on hand-built contexts.
- `test/`: the built module run on contexts whose bodies the Lattice SDK
  encodes (`node --test`).
- `host-check/`: a Swift package that runs the module through Lattice's own
  evaluator (determinism scan, exports), prints its CID, replays the JS
  suite's recorded contexts and checks the spec names the module.

## Build

```bash
cargo build --release --target wasm32-unknown-unknown
cp target/wasm32-unknown-unknown/release/skylot_policy.wasm ../chain/
```

`rust-toolchain.toml` pins the compiler, because the module's bytes, and so
its CID, depend on it. After a change, put the CID host-check prints into
`../chain/spec.json` and this README.

When `chain/rules.json` changes:

```bash
node tools/gen-rules.mjs
```

## Test

```bash
# Native unit tests, including rules.rs against chain/rules.json.
cargo test

# The built module, on SDK-encoded bodies, recording each context.
# LATTICE_SDK defaults to ../../lattice-sdk/packages/sdk/dist/index.js.
cargo build --release --target wasm32-unknown-unknown
CONTEXT_DIR=/tmp/skylot-contexts node --test test/policy.test.mjs

# Lattice's own evaluator: CID, genesis validation, the recorded verdicts,
# and the spec's moduleCID. Use a fresh CONTEXT_DIR for each run.
(cd host-check && swift build -c release)
host-check/.build/release/host-check ../chain/skylot_policy.wasm /tmp/skylot-contexts ../chain/spec.json
```

The JS suite also fails if `chain/skylot_policy.wasm` isn't the module under
test, or if `chain/spec.json` doesn't name that module's CID.

`host-check` depends on the Lattice checkout at `../../../Lattice` by path,
and its `Package.resolved` is Lattice's own (a fresh resolve picks a
`swift-system` that WasmKit doesn't build against). For CI, pin Lattice by
tag instead.

## Decisions the spec leaves open

- A building's `at` must be within 10 minutes of the block's timestamp,
  in either direction, whenever it changes, including when the building is
  created.
- Buying a lot held by the burn address pays the burn address, so that
  payment is added to the transaction's burn total. Otherwise the same credit
  would pay for the lot and for a claim.
- A brand is refused if it contains `image/svg` in any letter case, or with
  the slash JSON-escaped (`image\/svg`).
- `user/<a>/<rest>` needs a non-empty `<a>` and `<rest>`. A brand, like any
  other user record, may be deleted by its owner.
